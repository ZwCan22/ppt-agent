# 从能运行到能维护

## 分层：让每层有明确职责

页面收集需求和展示状态；API 负责身份、校验、保存、查询和下载；数据库保存事实；Worker 执行耗时制作；Dify 组织模型工作流；渲染器把合法大纲变成 PPTX。

大纲错误看接入与校验，布局错误看渲染器，排队不动看 Worker。先定位责任层，再改代码，避免同时动所有地方。

## 异步任务：接收成功不等于制作完成

201 表示任务已保存，浏览器暂时断网不代表制作失败。用原任务编号继续查询。数据库状态、领取次数、执行凭证和到期时间帮助进程重启后恢复处理。

## 幂等：识别同一次提交

客户端先生成提交编号，网络不确定时沿用编号与原需求。数据库的用户加提交编号唯一约束协调重复与并发。同一用户的新制作意图使用新编号，不同用户互不影响。

先查再插入在并发下仍可能重复。ON CONFLICT 与数据库唯一约束决定谁创建，测试用两个真实连接同时验证。

## 租约：Worker 必须仍有资格写结果

领取产生 execution_token 和到期时间，心跳续期，过期任务被回收。写状态同时核对任务、原状态、凭证、未过期条件。旧 Worker 完成后也不能覆盖新 Worker；每次执行独立文件夹保护文件。

## 测试：检查规则和实际数据

返回 200 还要看编号；重试还要看数据库只有一条；拒绝他人下载还要验证所有者能下载相同文件。正向、反向一起保护规则。

登录测试串起密码、Cookie、数据库会话、到期与退出。迁移测试从空库执行历史版本，create_all 不能证明迁移链可运行。

夹具是准备与清理测试环境的代码。普通测试回滚事务；并发测试真实提交到临时 Schema；迁移测试用临时数据库。共用准备放 support.py，业务断言放不同测试文件。

## CI：换一个干净环境重复验收

GitHub 从仓库取代码、按锁文件安装、启动临时数据库、执行检查。前端 storage 曾被 gitignore 误忽略，就是 CI 发现的本机与仓库差异。

CI 报告证据，是否强制阻止合并由仓库规则决定，不能只因有 workflow 就认为 main 已受强制保护。

## Git 与交付

分支集中一轮工作，PR 写目的、范围、验证，合并后本机同步。锁文件、配置模板、迁移、容器、日志、健康检查和备份决定别人能否接手。备份应恢复并打开对应文件验证。

## 学习路线与验收目标

1. Python 函数、类、异常、with：读懂一次请求调用链。
2. HTTP、JSON、状态码、Cookie：解释提交和轮询。
3. SQL、事务、唯一约束、索引、锁：解释并发为什么不能只靠 if。
4. FastAPI 依赖、Pydantic、SQLAlchemy：独立增加一个小接口。
5. 单元/集成测试、夹具、替代依赖：写预期并验证失败路径。
6. Git、PR、CI、Docker、锁文件：交付可重复构建的版本。
7. 日志、备份、恢复、发布：定位并处理一次真实故障。

每阶段以自己完成一个小改动、讲清目的、数据流、失败路径和验证证据为目标，不以背诵框架名称为目标。
